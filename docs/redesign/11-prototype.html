    The outbox pattern, and the five ways it fails in Postgres

    A home-made outbox skips events, bloats, stalls when you drop partitions, and its CDC slot can fill the disk. Each failure reproduced on Postgres 16, with the fix.

    The fix is an outbox: write the event into a table in the same transaction, and let a relay publish it. On a whiteboard that's a table and a loop. What follows is how that loop breaks, reproduced on Postgres 16.

    01The poller that skips rows

    The obvious relay remembers the highest id it published and asks for anything newer. It loses an event whenever two transactions commit in a different order from the one their ids were handed out in, because a assigns ids on insert, not on commit.

      03Dropping partitions without stalling the poller

      DROP TABLE on a partition needs an ACCESS EXCLUSIVE lock on the parent, and every new query queues behind it. In the test the poller waited 3.04 s; with DETACH … CONCURRENTLY first, 0.036 s.
