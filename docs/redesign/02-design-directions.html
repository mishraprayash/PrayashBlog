The Transactional Outbox Pattern: Why Your 100-Line Script Breaks in Production

This code has a bug that won't show up in review or in staging:

await db.orders.create({ data: order });
await kafka.send({ topic: 'orders', message: order });

Fig. 1 — The dual write.

If the Kafka call fails after the insert commits, the order exists and nothing downstream hears about it. Billing never charges, and no error shows up anywhere, because the database call already returned successfully.

The ghost row problem

The obvious poller pages by id. Under READ COMMITTED, a transaction that took its id earlier but commits later is skipped for good.

Revised 18 Oct 2026. Fixed the worker-sharding query: % 4 produced negative buckets for about a third of keys.
Tested on Postgres 16. The race needs two concurrent writers, so a single-connection test won't show it.
